# VERIFY — 0.2.2-rc.1-v1.5.1

> 本版只修「系统通知」这一行里**「测试通知」按钮的交互与反馈**；通知本身的形状、权限模型、
> 完成边沿、探针与设置 Schema 都不变。

## 1. 问题与根因

用户在浏览器里授权了通知之后，点「测试通知」没有任何反应。

两条原因叠在一起：

1. 按钮的 `disabled` 绑在组件挂载时读到的 `notificationPermission()` 上。用户在页面外
   （地址栏 / 站点设置）授权、或授权发生在挂载之后时，这个 state 不会自己变，按钮一直停在禁用态。
2. 就算点击真的执行了，`showCompletionNotification` 失败也只是静默返回 `false`，界面没有任何
   结果——用户分不清「按钮禁用」「权限没给」「系统把横幅吞了」。

## 2. 改动

| 位置 | 改动 |
| --- | --- |
| `client.js` | 「测试通知」按钮只在环境确实没有 `Notification`（`unsupported`）时禁用；点击时实时读 / 请求权限，并在行内显示结果（已发出 / 没授予 / 发出失败）。权限状态在 `focus` 与 `visibilitychange` 时重新同步。测试通知用唯一的会话 id（`preview-<时间戳>`）派生 tag，连点两次也不会被浏览器当成「同一会话替换」静默吞掉。 |
| `test/client.test.mjs` | 新增 1 项：点「测试通知」会真的发出一条并显示「已发出」；没权限时显示「没有授予通知权限」且不假装发过。 |
| 文档 | `AGENTS.md` 3.11 补按钮行为；`docs/PITFALLS.md` 新增坑 ⑬（排障入口不能依赖会过期的状态、不能静默失败）；`README.md` 与测试数同步。 |
